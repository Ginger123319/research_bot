# 调研小助手（Ginger） 

> **行动代号来源**：「Ginger」源自同名香料——生姜。姜性辛辣，能提神开窍、去腐生新；古语有云「姜还是老的辣」，寓意历经沉淀、洞察愈深。本项目以此为名，寓意调研小助手如姜般，以敏锐的嗅觉穿透信息噪声，辅助判断、直达要害。

---

## 调研 SOP 流程

### 阶段一：需求澄清

- 明确调研目标（是什么？为什么要做？）
- 确认输出形式（报告 / 对比表 / 摘要？）
- 确认时间范围、信息来源限制
- 识别关键决策人及其关注点

### 阶段二：问题拆解

将复杂问题分解为可独立搜集、可验证的子问题，是调研质量的核心枢纽。

**常用拆解方法：**

| 方法 | 适用场景 | 示例 |
|------|----------|------|
| **问题树（Issue Tree）** | 结构化分析、咨询类问题 | 「为什么性能差」→ 硬件瓶颈 / 框架效率 / 数据吞吐 |
| **5W1H** | 现象理解、事件溯源 | What / Why / Who / When / Where / How |
| **维度拆分** | 对比评估、选型类问题 | 从吞吐量、延迟、易用性、生态四个维度各自展开 |
| **时间轴拆分** | 演进类、趋势类问题 | 拆为「现状 / 近期变化 / 未来趋势」三段 |

**拆解原则：**
- 子问题之间相互独立（MECE 原则：不重叠、不遗漏）
- 每个子问题应可独立被回答
- 子问题数量控制在 3～7 个，过多则需再次归并

### 阶段三：信息搜集

- 按子问题逐一检索，避免漫无目的地收集
- 并行检索多个来源（文档、论文、内部数据、网络）
- 记录来源，保留原始引用
- 发现新子问题时，回到阶段二补充拆解

### 阶段四：筛选与去噪

- 去除冗余、过时、不可信的信息
- 交叉验证关键数据点（至少两个独立来源）
- 标注不确定项，区分「事实」与「观点」

### 阶段五：整理与分析

- 将子问题的答案还原到问题树结构中
- 提炼跨子问题的共性规律与关键差异
- 形成初步结论，标注结论的置信度与依据强度

### 阶段六：输出与交付

- 按约定格式撰写报告
- 结论前置，支撑依据分层展开（结论 → 论据 → 来源）
- 附上参考来源，标注置信度
- 主动说明调研局限性（哪些问题未能充分覆盖）

## 示例：调研「国内主流大模型推理服务部署方案」

| 阶段 | 具体动作 |
|------|----------|
| **需求澄清** | 目标：为新模型选型推理框架；输出：对比表 + 推荐意见；范围：2025 年以后版本，限国内可用方案 |
| **问题拆解** | ① 各框架核心能力如何？② 性能表现（吞吐 / 延迟）差异？③ 运维复杂度？④ 社区活跃度与长期可维护性？⑤ 已有内部使用经验？ |
| **信息搜集** | 按 5 个子问题分别检索官方文档、GitHub Issues、技术博客、内部部署记录 |
| **筛选去噪** | 排除版本过旧的测评；标注「社区反馈」与「官方声明」的差异；剔除无法复现的性能数据 |
| **整理分析** | 建立四维对比矩阵；发现 vLLM 在动态批处理上有明显优势，TRT-LLM 延迟更低但运维成本高 |
| **输出交付** | Markdown 报告：结论前置（推荐 vLLM）→ 分维度对比表 → 各框架适用场景说明 → 参考来源列表 |

## Runbook 生成（可执行骨架）

项目新增一个脚本用于生成“Runbook 交付物”的骨架，并做来源 URL 的可访问性检测（ok/blocked/not_found），自动落盘到：

- `docs/results/YYYY-MM-DD-<topic>-runbook.md`
- `docs/sessions/NN_<topic>_research.md`

### 用法

```bash
python3 scripts/research_runbook.py \
  --topic "sglang-pd-disagg" \
  --problem "SGLang 的 PD 分离部署" \
  --success "prefill/decode 请求命中不同后端且吞吐恢复到目标值" \
  --env "k8s, sglang vX.Y, 2x nodes" \
  --keyword "pd separation" \
  --keyword "disaggregated serving" \
  --seed-url "https://github.com/sgl-project/sglang" \
  --seed-url "https://arxiv.org"
```

> 说明：脚本本身不做全网检索，主要用于“产出模板 + 记录候选来源 + access 检测”。全网检索与相关度/权威性判断仍按调研 SOP 与设计文档执行。
