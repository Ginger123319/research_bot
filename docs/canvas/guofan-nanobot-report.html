// 01 · PROBLEM

手工评估的三大痛点

将一个 LLM 模型从部署到出具评估报告，过去需要人工干预每一步

⚙️
步骤繁琐，全程人工
部署 → 探针 → 数据集 → 压测 → 分析 → 报告，每个环节都需要切换脚本、手动传参，一个模型完整走完需 2~3 天。
每模型手工介入 15+ 次
🔁
脚本分散，难以复用
不同模型的压测脚本各自定制，参数命名不统一，下一个模型开始时几乎从零开始，经验无法沉淀。
跨模型重复劳动 ~60%
🔍
过程黑盒，出错难定位
压测命令跑在远端 GPU 服务器，执行过程不可见；EAGLE3 avg_output_len 高估、Phase 3 并发污染等问题，发现滞后。
1 次根因排查平均耗时 4h+
↓ nanobot + Skills 的解法
// 02 · SOLUTION · WORKSPACE

Workspace：给 Agent 的"工程记忆"

5 个结构化文件，将项目知识、行为规程、陷阱规则注入 Agent 上下文

⚡ AGENTS.md 行为规程 + 触发规则
🧠 MEMORY.md 技术记忆 + 项目状态
🎭 SOUL.md 人格 + 思维风格
👤 USER.md 用户画像 + 偏好
🛠️ TOOLS.md 工具链索引 + 执行规范
# AGENTS.md · 行为规程
  • 12 个 guofan Skill 的触发关键词映射表（自然语言 → Skill 文件路径）
  • 高频陷阱库：benchmark 成功率计算、avg_output_len 高估、Phase 3 并发污染等 8 条规则
  • 远端写权限白名单（gpu_l20_6_direct 路径范围）
  • 强制行为：遇到 guofan 任务先 read Skill，禁止自行写临时脚本
  • 会话结束触发：更新 progress.md + project_status.md

🔑 关键设计：Skill 作为"行为说明书"
SKILL.md 不是代码，而是 LLM 可读的结构化指令。Agent 读取后严格按步骤执行，确保每次评估流程一致、可审计。

📊 qps-peak-finder 核心价值
