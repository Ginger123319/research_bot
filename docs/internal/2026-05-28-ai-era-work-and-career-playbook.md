# AI 时代工作方式与职业发展手册（个人作战手册）

> 写于：2026-05-28
> 背景：AI-Infra 工程师，正在适配两层 agent（任务执行层 + 外接大脑）的新工作模式
> 用途：每月翻一次校准方向；每周用第五章的清单复盘；自我怀疑时翻第四章

---

## 0. 核心命题

```
工具变强，对「动脑、定方向、做判断」的要求不是更低，而是更高。
```

我的角色已经从「亲手搬砖」变成「包工头 + 设计师 + 优化器」：

- **任务执行层 agent**（Cursor / 各类 coding agent）：我发命令，它执行
- **外接大脑 agent**（豆包 / Claude / GPT）：我主导方向，它帮我校准
- **我自己**：相当于模型训练里的 `optimizer`——控制执行层 agent 的方向和步长，朝既定目标收敛，直到它每次都能正确解决一类问题，且具备一定泛化性

我的不可替代性 = **定义问题 + 判断结果 + 承担选择 + 沉淀方法论**。

「自己亲手做」不再是产能，而是退化成「校准样本」。真正的产能在两层 agent 上；我对自己的考核标准是：**有多少类问题已经能"一句话解决"了**。

## 一、两层 Agent 工作方式

### 1.1 心智模型

```
                      ┌─────────────────────────┐
                      │   我（人 = optimizer）   │
                      │  定方向 / 判断 / 担责    │
                      └────────────┬────────────┘
                                   │
                ┌──────────────────┼──────────────────┐
                │                                     │
       ┌────────▼────────┐                  ┌─────────▼────────┐
       │  外接大脑 agent  │  ←—— 校准 ——→   │  任务执行层 agent │
       │  豆包/Claude     │                  │  Cursor/Codex    │
       │  探索 + 思考     │                  │  实际改代码/跑命令 │
       └─────────────────┘                  └──────────────────┘
```

**两层的分工**：

| 层 | 我的输入 | 它的输出 | 我的产物 |
|----|---------|---------|---------|
| 外接大脑 | 含糊的问题、半成型的想法 | 框架、对比、风险点、备选方案 | 校准过的方向 + 判断标尺 |
| 任务执行层 | 明确的目标 + 约束 + 交付标准 | 代码/命令/文档/数据产物 | 经过我审核+优化的成品 |

**关键纪律**：
- **外接大脑**：我主导方向、决定问什么，AI 回答不能直接当结论用，要再过一次自己的判断
- **任务执行层**：必须用结构化指令（见 1.3），不能用模糊语言

### 1.2 Skill 沉淀的 5 步闭环

这是我的核心产能积累机制。每一类反复出现的操作，都要走完这个闭环：

```
1. 自己做一遍           ←  建立"正确"参考样本
        ↓
2. 教会 AI 做           ←  写成 SKILL.md / prompt 模板
        ↓
3. 让 AI 做（一句话）    ←  开始用 agent 调度
        ↓
4. 出错记录             ←  用自己经验 + AI 辅助判断，写进 skill
        ↓
5. 强化迭代             ←  直到大概率能正确完成
        ↓
   skill 化成功
```

**操作准则**：
- 凡是**重复 ≥ 3 次**的操作，必须沉淀为 skill 候选
- 每个新需求，先问自己：**能不能用一句话让 AI 帮我做？卡在哪里，哪里就是 skill 缺口**
- 已有的 skill 集合见 `docs/planning/skills-roadmap.md`，每月对照一次新增需求 → skill 候选

**目标**：「一句话解决一类问题」。能解决的类别越多，我作为 optimizer 的价值就越大。

### 1.3 从问题冒出到指令发出：分流 → 选层 → 选格式

> **核心观念**：AI 让"问问题"变得太便宜了，所以稀缺资源不再是"该怎么问"，而是 **"该不该问、该问谁、问完拿来干嘛"**。这一步比四件套还要前置。

完整链路三步走：

```
冒出一个问题 / 想问 AI / 想发指令
        ↓
【第一步】问题分流（5 秒判断它和我终极目标的关系）
        ↓
【第二步】选层（执行层 / 外接大脑 / 自己处理 / 丢弃）
        ↓
【第三步】发指令的标准格式（四件套 + 分场景降级）
```

#### 第一步：问题分流（5 秒判断）

每个冒出的问题，先在心里和**终极目标 4 个对照锚点**对一遍：

| 锚点 | 在哪里看 |
|------|---------|
| 当前周 / 月在推进什么 | `progress.md` |
| 年内技术成长目标 | [ai-infra-career-and-profiling-roadmap.md](./ai-infra-career-and-profiling-roadmap.md) 阶段 0-3 |
| 3 年画像 | 同上「三年后的目标画像」一节 |
| 个人本色 | 本手册 4.4 节 |

然后做这个**5 类分流**：

| 关系类型 | 含义 | 怎么处理 |
|---------|------|---------|
| **直接相关** | 推进当前核心目标 / 工作主线 | **立即做**，进第二步 |
| **间接相关** | 为核心目标储备能力/认知 | 见下面「间接相关的细化处理」——不是简单的"紧急→做，不紧急→池子" |
| **无关好奇** | 纯求知 / 业内八卦 / 顺便想知道 | **进「好奇心账本」**，周日固定 1 小时批量消化 |
| **反向相关** | 看起来相关但会消耗时间/带偏方向（如「研究下新出的某框架」） | **立刻丢弃**，记一笔「差点踩坑」进避坑清单 |
| **工作之外的纯放松** | 看剧、聊天、打游戏 | **不强求都进体系**——该放松就放松，但不要混淆「放松」和「学习」 |

#### 分流的灰色地带：间接相关 vs 无关好奇

这两类最容易混淆，混淆了就会要么把好奇心当能力储备（浪费时间），要么把能力储备当好奇心（错过关键直觉）。

**关键判别问句**：

> **"这个答案会改变我未来做某件事时的判断吗？还是答完就忘？"**

| 答案 | 归类 |
|------|------|
| 会改变我的行为（形成**可调用的操作启发式**） | 间接相关，是能力储备 |
| 答完瞬间满足，不改变行为 | 无关好奇 |

**什么是「操作启发式」**：

> 一条可写下来的、**未来遇到类似场景能直接调用**的判断规则。比如：
> - "看到训练 MFU < 30%，第一反应是看 PP bubble 而不是 TP 通信"
> - "看到容器内有人 rm -rf /，第一反应是检查 -v 挂载，而不是恐慌"
> - "看到 PR 改了 100+ 文件，第一反应是拆分而不是 review"
>
> 这是 AI-infra 工程师**最稀缺、最不被 AI 替代**的资产之一（见 3.3.1 节"系统思维"）。AI 能告诉你事实，但启发式必须自己沉淀。

#### 间接相关的细化处理（避免"全进池子全忘了"陷阱）

「间接相关」不是简单的"紧急→做、不紧急→池子"，而是要看**答案能不能立刻沉淀**：

| 条件 | 处理 | 理由 |
|------|------|------|
| **紧急**（卡住当前任务） | 立即做 | 不解释 |
| **不紧急 + < 10 分钟能拿到答案 + 能写下一条操作启发式** | **当场做**，并把启发式写进笔记 | 形成启发式的最佳时机是问题刚冒出来的时候——延后会忘了为什么问、为什么重要 |
| **不紧急 + 需要 > 10 分钟深度学习**（如读一篇论文） | 进**待办池**，标注"为什么重要" | 深度学习需要整块时间，碎片化做反而低效 |
| **不紧急 + 答完没法形成具体启发式**（其实是泛泛好奇） | 重新归类为「无关好奇」，进好奇心账本 | 自检：是不是把好奇心包装成"能力储备"在自我欺骗 |

**纪律**：每个"当场做"的间接相关任务，**必须产出一条写下来的启发式**。没写下来 = 没做完。这是把碎片知识转成长期资产的关键动作。

启发式的沉淀位置建议：
- AI-Infra 相关 → `docs/internal/infra-heuristics.md`（待建）
- 一般工程实践 → `docs/internal/engineering-heuristics.md`（待建）
- AI 协作相关 → `docs/internal/ai-pitfalls.md`（即 1.5 节提到的避坑清单）

#### 第二步：选哪一层 agent

判断这个问题应该问谁：

| 问题性质 | 去哪一层 | 例子 |
|---------|---------|------|
| 任务执行（写代码/改文档/跑命令/查资料） | **任务执行层** agent（Cursor 等） | "在 X 文件加 Y 函数" |
| 认知澄清（探索方向/对比方案/咨询观点） | **外接大脑** agent（豆包/Claude） | "用 LoRA 还是全参 SFT，trade-off 是什么" |
| 我自己都没想清楚要什么 | **先去外接大脑**澄清需求，再回到执行层 | "我现在卡在 X，我应该问什么问题" |
| 5 分钟内能自己做完 | **不去 agent**，自己干 | 改个 typo / 看一眼文件 |
| 决策/担责类（要不要做 X、值不值得投入） | **AI 只能给信息，最终自己判断** | "要不要离职去 XX 公司" |

#### 第三步：发指令的标准格式（每次必写）

杜绝「随便让 AI 做」。每次发指令必写四件事：

```
目标：    最终要解决什么问题（不是要做什么动作，是要拿到什么结果）
约束：    边界 / 红线 / 不能动的依赖 / 时间预算
交付标准：怎样才算成功（可观测、可验证）
校验方式：我打算怎么验证 AI 输出是对的
```

**反例**：「写个方案」
**正例**：「目标是说服客户接受低价方案；约束：不能贬低竞品、篇幅 2 页内；交付：可直接发送的 markdown；校验：我会拿我之前成功的 3 个案例对照逻辑」

#### 分场景的降级版（不是每次都要硬填四件）

四件套是**最完整版**，但不同任务类型应该有不同的最低要求。强求每次都填满，反而会让你在轻量任务上摩擦过大、放弃使用。

| 任务类型 | 必填 | 可降级/可省 | 例子 |
|---------|------|------------|------|
| **实现型** <br>（写代码 / 改文档 / 跑流程） | 目标 ✅ 约束 ✅ 交付标准 ✅ 校验方式 ✅ | 不可省 | "在 X 文件里加一个 Y 函数，签名 Z，要通过单测 T" |
| **探索型** <br>（调研 / 对比 / 选型 / 咨询） | 目标 ✅ 约束 ✅ + **"判断有用的 1-2 个标准"** | 交付标准 / 校验方式**降级**为"判断有用的标准" | "我想搞清楚 X，结果对我有用的标准是：能让我在 A 和 B 之间做出选择" |
| **开放对话** <br>（聊天 / 求意见 / 头脑风暴） | 目标 ✅（哪怕只是「我想搞清楚 X」） | 其余可省，**但事后必走 1.4 三步校验** | "你怎么看 X 趋势" |
| **琐事** <br>（一次性转换 / 格式化） | 目标 ✅ 交付标准 ✅ | 约束 / 校验可口头省 | "把这段 markdown 转成 JSON 数组" |

#### 想不到交付标准/校验方式怎么办

「想不到」本身就是一个**有意义的信号**，先做这个自问：

> **"如果我现在不让 AI 做，自己来做，我会知道做完了吗？"**

根据答案分三种情况处理：

| 情况 | 信号意义 | 应对 |
|------|---------|-----|
| **A. 知道——只是没写下来** | 偷懒了，要警觉 | 强制 30 秒反向追问："这件事做完了，我怎么算它成功？"逼自己至少给出**一个观察点**，再发指令 |
| **B. 不知道——任务本身就是探索性的** | 正常，是探索型任务 | 用降级版的「判断有用的 1-2 个标准」代替交付/校验 |
| **C. 连"我到底要什么"都说不清** | 还没想清楚 | **先用外接大脑澄清需求**（"我现在的状态是这样，我应该问什么问题？"），再发指令给执行层 |

**边界纪律**（两层 agent 工作方式的核心）：

> **执行层 agent 的输入质量 = 我和外接大脑澄清的质量。**
> 想不出校验方式的任务，绝不直接扔给执行层——那等于让它在我自己都没想清楚的需求上盲跑。

#### 三个分流时要警觉的陷阱

| 陷阱 | 症状 | 触发的处理 |
|------|------|----------|
| **「反正问 AI 不费事」陷阱** | 顺手就开始问，不做分流判断 | 问问题免费，但**接收答案的注意力是宝贵的**。每问一个无关问题，都在消耗判断力带宽 |
| **「好奇心拖着走」陷阱** | 连续 5 个「顺便问一下」，2 小时没了 | 强制走分流——无关好奇必须进好奇心账本，**不能即时消化** |
| **「看起来相关」陷阱** | 新出的某热门技术看起来和方向相关，其实只是热闹 | 用 4 个目标锚点严格对照，**对不上就是反向相关，立刻丢弃** |

#### 配套机制：好奇心账本

为了**不压抑好奇心、又不被它带偏**，建一个独立的暂存机制：

- **位置**：`docs/scratch/curiosity-log.md`（待建）
- **写什么**：每次冒出的「无关好奇」问题，一句话写进去（不展开）
- **何时消化**：每周日固定 1 小时，批量过一遍
  - 大部分会发现：当时觉得有趣，一周后已经不想看了 → 删掉
  - 少数会发现：还是有兴趣 → 升级为「间接相关」放进待办池
  - 极少数会发现：突然想通和主线的连接 → 升级为「直接相关」立即做

**这个机制的本质**：把「即时满足好奇心」的冲动延迟一周，让你的判断力做过滤，而不是让 AI 的无门槛回答消耗你的注意力。

#### 实战示例（从问题冒出到指令发出）

场景：周二下午跑训练 job，等结果时脑子里冒出四个问题：

```
Q1: "看到了 zero bubble v2 的新论文，要不要看一下"
Q2: "今天的 235B job MFU 是 27%，怎么定位是哪一层的瓶颈"
Q3: "Cursor 新出的 Composer 模式好像挺好用的，要不要试试"
Q4: "docker 容器里如果 rm -rf /，对宿主机有什么影响？"
```

走完三步分流：

| 问题 | 第一步分流 | 第二步选层 | 第三步指令/动作 |
|------|----------|-----------|----------------|
| Q1 | **无关好奇**（zero bubble v1 已经在路线图，v2 不是当前主线） | 不去 agent | **进好奇心账本**，周日批量消化 |
| Q2 | **直接相关**（profiling 路线图阶段 0 任务） | 任务执行层 | 实现型四件套全填：目标=出第一张时间分布表；约束=不改训练脚本；交付=填完路线图 1.3 节的那张表；校验=每项百分比加起来 ≈ 100% |
| Q3 | **反向相关**（"看起来提效"，实际是切换工具的成本+学习成本，本周主线不在工具） | 不去 agent | **立刻丢弃** + 记一笔「Cursor 新功能折腾陷阱」进避坑清单 |
| Q4 | **间接相关 + < 10 分钟 + 能形成启发式**（答完会改变未来"看到容器内破坏性操作时的判断"） | 外接大脑（交叉验证文档） | 探索型指令："目标=搞清楚容器 rm -rf / 的真实影响范围；判断有用的标准=能回答 '该不该紧急救火宿主机'"。**完成后必须写一条启发式进 `infra-heuristics.md`**，否则视为没做完 |

**Q4 的对照尤其值得注意**：它最容易被错判成"无关好奇"丢进账本（"反正不影响当前任务"），但实际上它是高价值的**操作启发式储备**——AI-infra 工程师天天用 docker 跑训练/推理，**生产环境的一次误判可能就是几小时停摆**。把它和 Q1（zero bubble v2 论文）做对比，能清楚看到「**会改变行为的知识** vs **答完就忘的好奇心**」的差别。

如果不做分流，四个问题都顺手问 AI——下午 2 小时就没了，且只有 Q2 真正推进了目标，Q4 拿到答案但没沉淀启发式，下次踩坑时依然恐慌。

### 1.4 AI 输出的三步校验

绝不允许「AI 给了就直接用」。三步必做：

1. **对标目标**：有没有偏离最初方向？偏了就打回重调，不将就
2. **查漏洞**：逻辑、常识、场景适配、风险点逐条挑错（AI 容易"想当然"、脱离现实）
3. **做优化**：至少做 1 处**结构性调整**（不是只改文字），注入我自己的经验和场景认知

**纪律**：每一份 AI 输出，至少改 1 个结构性的地方。直接复制粘贴一次，我就退化成了"通道"。

### 1.5 复盘机制

每次重要的 AI 协作结束，花 1 分钟回答：

- 最初方向对吗？中途有没有跑偏？
- AI 哪些回答靠谱、哪些踩坑？根因是什么？
- 这次的踩坑要不要进 **避坑清单** 或 **指令模板**？

长期积累两份资产：
- `docs/internal/ai-pitfalls.md`（待建）：AI 协作避坑清单
- `docs/internal/prompt-templates.md`（待建）：高效指令模板库

## 二、动脑、定方向、判断力的专门训练

工具变强，对人脑核心能力的要求更高。这一章把训练拆成两块：**用 AI 中** + **用 AI 之外**。

### 2.1 用 AI 过程中的训练（边用边练）

**A. 发指令前先定目标**
- 严格遵守 1.3 的四件套：目标 / 约束 / 交付标准 / 校验方式
- 自问一遍："这件事最终要解决什么？底线是什么？" 答不出来就不发指令

**B. 同一目标用 2-3 个方向产出**
- 在重要决策上，强迫自己让 AI 给出 2-3 个不同方向
- 自己做方向取舍 → 锻炼定方向能力

**C. 审产出三步法**（见 1.4）

**D. 放权 + 把关，不包办也不躺平**
- 执行细节全交给 agent，我只抓顶层方向 + 关键节点 + 最终拍板
- 多选结果时**限时决策**（小事 10 秒、大事不超过 1 小时），不反复纠结，锻炼决断力

**E. 复盘对话**（见 1.5）

### 2.2 用 AI 之外的训练（底层能力打基础）

这部分是**离开 AI 也带得走的认知资产**，比 AI 协同技巧更重要。

#### 2.2.1 思维训练：三层提问拆问题

任何事情先用三层提问梳理一遍再行动：

```
1. 本质问题是什么？     ←  拨开表面现象，看真问题
2. 核心诉求有几个？     ←  分清主次和优先级
3. 最优路径/底线是什么？ ←  划定边界和兜底方案
```

日常练习场景：点餐、规划行程、安排工作——都先想"目标 + 优先级"再行动。

#### 2.2.2 决策训练：建立判断标尺

```
四个维度的打分标尺：
  成本（时间 / 钱 / 注意力 / 机会成本）
  风险（最坏结果 / 可逆性 / 影响面）
  收益（短期 / 长期 / 可量化部分）
  长期价值（3 年后还有意义吗）
```

**两类决策两种处理**：
- **小事**：限时 10 秒拍板，杜绝内耗
- **大事**：收集关键信息 → 列利弊 → 设定最坏结果能否承受 → 拍板

**每周必做**：复盘 1 个过往决策（当初判断依据 / 结果 / 哪里没考虑到）。

#### 2.2.3 输入沉淀：搭建认知底座

**少碎片化刷信息，定向积累**：
- 行业规律 / 风险案例 / 人情逻辑 / 历史模式

**读资料时反向追问**：
- 作者的立场是什么？
- 他的逻辑链条是什么？
- 他默认的隐藏前提是什么？

这是 AI 没有的"专属阅历"——AI 知识没有立场，我有。

#### 2.2.4 模拟推演：反向预判风险

拿到一个方案/想法，主动做反向推演：
- 这么做会引发什么问题？
- 有哪些意外情况？
- 如何兜底？
- 假设方案 A 失败，B/C 是否可行？

这是**全局视角**和**最坏情况思维**的训练。

#### 2.2.5 控制依赖：保留无 AI 时间

- **重要事项**：先自己独立想出完整思路，再用 AI 辅助优化（顺序很关键，不能颠倒）
- **每周留半天「无 AI 时间」**：纯靠自己分析、解决问题，避免思维肌肉萎缩

**禁忌**：
- 不允许"上来就求助 AI"成为默认行为
- 不允许把 AI 当遇事即用的"外脑义肢"——它该是杠杆，不是支架

## 三、职业发展方向与可迁移能力

### 3.1 三个最稳的方向（2026 年）

**1）AI + 业务复合型**（最匹配我的现状）
- 定位：懂业务、会用 AI、能落地结果的人
- 在我的语境里：**AI-Infra + 模型业务方向**——让我的框架/优化能力直接服务于公司最重要的模型建设
- 风险：如果脱离业务、只做"通用 infra"，会逐渐失去话语权

**2）人机协作架构师 / 工作流设计**
- 定位：指挥多个 Agent、设计流程、评估输出
- 在我的语境里：我现在做的"两层 agent + skill 沉淀"就是这条路的雏形
- 关键：要从"自己会用"升级到"能设计/教别人用"

**3）垂直领域专家（+ AI 工具化）**
- 定位：行业深度 + AI 提效
- 在我的语境里：**ML Systems 方向的 profiling + 优化专家**——见 [ai-infra-career-and-profiling-roadmap.md](./ai-infra-career-and-profiling-roadmap.md)
- 这是我的"本钱"，AI 协同是"杠杆"，不能颠倒

### 3.2 三个要避开的方向

| 方向 | 为什么避开 |
|------|----------|
| 纯执行（数据录入、基础报表） | AI 替代率 >80% |
| 纯流程（标准化文案、SOP 执行） | AI 替代率 >80% |
| 纯工具操作（专门"按按钮"的活） | 工具变了就归零 |

### 3.3 离职后还值钱的可迁移能力清单

这是核心资产清单——**离开当前公司还能带走、且市场认的能力**。

#### 3.3.1 思维与决策类（最值钱，跨行业通用）

| 能力 | AI-infra 工程师的检验场景 |
|------|------------------------|
| 问题定义 | 从模糊的"训练慢"需求里抓住"是 PP bubble 还是 EP A2A 瓶颈"这个真问题 |
| 灰度决策 | profile 数据不全时，能拍板"先优化哪一项" |
| 系统思维 | 看到 MFU 低，能从 Layer 4 一路下钻到 Layer 1，找到根因 |
| 批判性思考 | 能查出 AI 给的优化建议的逻辑漏洞和场景不适配 |

#### 3.3.2 AI 协同能力（2026 标配）

| 能力 | 检验场景 |
|------|--------|
| 提示词架构 | 写出"目标+约束+格式+校验标准"的指令，不是随便说说 |
| 多 Agent 调度 | 多个 AI 分工协作、合并结果、避免冲突 |
| 输出校验与优化 | AI 出初稿，我做结构调整、逻辑闭环、风险把关 |
| 工具栈熟练度 | Cursor / Claude / GPT / 推理框架 / Nsight 工具栈 |

#### 3.3.3 业务与商业能力（换行业也能复用）

| 能力 | AI-infra 语境 |
|------|-------------|
| 行业洞察 | 知道 MoE、推理 vs 训练支出占比、关键玩家的技术路线 |
| 价值转化 | 把"框架 MFU +20%" 转化成"模型迭代速度 +X% / 成本 -Y%"的业务语言 |
| 项目闭环 | 目标 → 计划 → 资源 → 执行 → 复盘 |
| 数据解读 | 看 profile / benchmark 数据，找异常、挖原因、提对策 |

#### 3.3.4 软技能（AI 永远替代不了）

| 能力 | AI-infra 语境 |
|------|-------------|
| 沟通与共情 | 听懂算法团队"训练慢"背后的真实诉求 |
| 创造力与审美 | 在多个可行方案里选出"优雅"的那一个 |
| 资源整合 | 跨部门把 infra 工作落到模型建设上 |
| 抗压与迭代 | 不确定性下稳定输出、知错就改 |

### 3.4 离职就清零的（停止投入）

| 类别 | 例子 |
|------|------|
| 公司专属流程 | 内部审批系统、特定 wiki 的路径、内部命名约定 |
| 只在内部认的头衔 | 部门 Level、内部人脉 |
| 纯执行熟练度 | 重复报表、模板化文案、纯调用专属内部工具 |

**纪律**：这些事情可以做，但不能投入"刻意练习"的注意力——它们是工作，不是能力建设。

### 3.5 可迁移能力的刻意经营

**每周**：
- 把当周做过的事 → 提炼能力 → 写出**可量化案例**（"用 X 方法在 Y 场景达成 Z 数字"）

**每季度**：
- 更新一页「可迁移能力 + 3 个备选岗位 + 简历亮点」
- 这一页是面试用的，不是 LinkedIn——重点是逻辑链清晰，不是关键字堆砌

**对外输出**（持续）：
- 技术短文 / AI 工具教程 / 案例分享
- 建立**个人品牌背书**——这是离职后唯一比"公司名"更值钱的资产

## 四、保持本色，不迷失方向

### 4.1 核心信念

```
AI 是工具，我是「定义目标、判断结果、承担选择」的人。
最终责任永远在人，AI 不背锅。
我的经验 = AI 的校准器，越懂业务越有价值。
```

### 4.2 三个 Anti-pattern（出现就警觉）

| Anti-pattern | 症状 | 修正 |
|--------------|------|------|
| **退化成通道** | AI 输出直接复制粘贴，不做结构性优化 | 1.4 三步校验严格执行 |
| **思维肌肉萎缩** | 遇事即问 AI，自己不再独立思考 | 2.2.5 无 AI 时间 + 决策训练 |
| **存在感焦虑** | 看到 AI 越来越强，焦虑自己被替代 | 把焦虑转化为：让 AI 做更多重复事，自己练判断力 |

### 4.3 每月一次的灵魂三问

每月最后一个周末，安静半小时回答：

1. **能力**：我过去 1 个月，做了哪些「离开公司也带得走的能力」？
2. **沉淀**：我把哪些重复操作沉淀成了 skill？还有哪些没沉淀？
3. **本色**：我有没有变成「只会指挥 AI 的中间层」？我的判断力比上个月强了吗？

第 3 题如果连续两个月答"没变强"，就要停下来检讨——很可能正在退化。

### 4.4 个人本色的定义

我的本色是「ML Systems 方向的工程师」，不是「AI 协作工具的运营人」。

**两条不能动摇**：
- **技术深度是本钱**：profiling + kernel + 系统设计——见 [ai-infra-career-and-profiling-roadmap.md](./ai-infra-career-and-profiling-roadmap.md)
- **AI 协同是杠杆**：放大本钱，不替代本钱

**纪律**：不能因为 AI 提效让我"完成任务变快"而放弃技术深度的积累。每周必须有**纯技术深度时间**（读论文 / 写 kernel / 看源码 / profile 实战），不允许全部时间都在"指挥 AI"。
