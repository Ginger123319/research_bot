## 1. 技术内核

### 1.1 NF4（4bit 量化格式）

1. NF4从名字上来看就可以知道几个量化的核心概念，分别是NormalFloat和4bit，即一种专门针对正态分布数据的4bit浮点量化格式，量化过程中存储4bit的索引值，反量化的时候通过索引值得到预先定义好的浮点值；这些浮点值是根据正态分布的特性计算得到的，固定的
2. NF4量化的工作机制为：通过工程经验，假设预训练模型的模型参数都符合正态分布，计算得到一张分位数速查表【保证在两个分位点之间的参数量相对均衡，在参数分布图上就是面积相当】，取值范围从-1～1共计16个浮点数，量化后存储的值就是这些浮点数对应的唯一索引值【0～15】；进入量化流程后，先对模型参数分块，块大小一般为64，然后Normalize到-1～1的区间，然后判断每个参数值离各个分位数的距离，距离最近的，就将这个值存储为这个分位数对应的索引值；在反量化的时候，通过索引值取到对应的浮点值，然后再做逆向的Normalize即可
3. 适用前提（接近钟形的预训练权重；随机初始化的权重不成立）

> **对我们的影响**：*对后续训练框架开发来说，是必须支持的特性，目前使用的模型的模型权重都满足接近钟形分布的这个条件*

### 1.2 Block-wise Quantization（量化策略）

1. 粒度选择：QLoRA 采用 per-block 量化（block_size 经验值 64），每个 block 内单独维护一个 fp32 的 absmax scale；和 §1.1 里 NF4 速查表的 16 个分位点是两个独立的设计——速查表只算一次、全局复用；scale 是每个 block 一份、随权重一起存
2. block_size 的 trade-off：block 越小，单个 scale 覆盖的参数越少，归一化更贴合块内真实分布、量化精度越高；但 scale 因子总数变多，fp32 scale 的额外显存开销也随之上升（具体到 0.5 bit/参数 的计算见 §1.3）
3. normalize 流程：每个 block 取 absmax 作为 scale → 块内参数除以 scale 归一化到 [-1, 1] → 在 NF4 速查表里找距离最近的分位点 → 存储该分位点对应的 4bit 索引；反量化时按 block 反向 normalize 即可

> **对我们的影响**：*block_size 建议做成可配置项（默认 64），便于针对不同模型规模 / 硬件做调优；但是否把这个配置真的暴露给用户、暴露到什么粒度，需要等框架选型确定后再决定*

### 1.3 Double Quantization（解决 §1.2 的开销）

1. 解决的问题：§1.2 引入了大量 fp32 absmax scale——block_size=64 时，每参数额外承担 32/64 = 0.5 bit 的显存开销；模型越大、block 越多，这部分越不可忽略
2. 做法：把这一层 fp32 scale 当作一组新的"待量化参数"再做一次量化——block_size = 256，目标精度 fp8；由于 absmax 都是正数（一侧分布），先减去均值居中后才适合做 0 点对称量化；这一步会再产生一组 fp32 的量化因子
3. 收益：每参数 scale 开销从 0.5 bit 降到 8/64 + 32/(256*64) ≈ 0.127 bit，节省约 0.373 bit/参数
4. 代价：反量化路径变成两层——先用 fp32 量化因子反量化得到 fp32 absmax scale，再用这个 scale 反量化得到原始权重；推理 / 训练前向反向中每次访问权重都要走这两步

> **对我们的影响**：*DQ 的收益取决于模型规模——参数量越大、block 越多，省下的显存越显著；代价是两层反量化的计算 overhead。是否默认开启、还是做成可选开关，等场景明确后再定*

### 1.4 Paged Optimizer

1. 实现机制：基于 NVIDIA Unified Memory，让一块 CPU RAM 可以和 GPU 直接通信；优化器状态在 GPU 显存不够时被自动 page 到 CPU，参数更新时再 page 回 GPU
2. 解决的问题：反向传播时的**瞬时**显存峰值导致的 OOM——也就是平均显存够用、只是某个瞬间冲顶；它和 NF4 / DQ 解决的"常态显存不够"不是同一维度的问题，本质是边界场景的兜底
3. 默认状态：一般不开——CPU↔GPU 传输延迟显著，会拖慢训练；只在确实遇到瞬时 OOM 时按需启用
4. 限制：依赖 NVIDIA Unified Memory，非 N 卡（如昇腾 NPU）不能直接复用这套机制

> **对我们的影响**：*建议做成可选开关、默认关闭；具体接入方式（是否对接训练框架的 optimizer 抽象层）等集成路径确定后再细化*
