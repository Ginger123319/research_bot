# SFT 本地复刻行动计划

> **启动前检查：** 动手前请先完成 [任务启动四步检查](task-kickoff-methodology.md)，确认目标锁定、机器锁定、方案有依据、步骤已写出。

目标：在本地 3 台 5880 上小规模复刻算法 SFT 流程，找到训练框架二开切入点。  
不追训练效果；第一轮不上 72B/122B/235B。

---

## 闭环步骤

### 1. 半天预跑

- 干什么：用官方 `ms-swift` 最小样例探路。
- 做到什么程度：知道 SFT 启动入口、配置长什么样；记录机器/GPU/磁盘/SSH；形成问题清单。
- 怎么验收：问题清单能标清卡在安装、数据、模型、分布式、日志还是 checkpoint。

### 2. 向算法拿材料

- 干什么：拿算法侧复刻所需最小材料。
- 做到什么程度：拿到配置、安装、模型、数据、评估、checkpoint、监控信息。
- 怎么验收：每类材料都有来源；没有的标“待算法补”。

### 3. 安装算法侧 `ms-swift`

- 干什么：在 3 台 5880 上安装算法改过的源码版 `ms-swift`。
- 做到什么程度：版本、commit、diff/patch、生效验证方式都记录下来；三台机器环境一致。
- 怎么验收：能证明本地用的是算法侧改动版，而不是官方版。

### 4. 准备本地小规模配置

- 干什么：把算法配置缩小成本地可跑版本。
- 做到什么程度：小模型、小数据、少 step；但保留 3 机分布式、eval、checkpoint、监控。
- 怎么验收：算法确认该配置可用于流程复刻，不用于比较效果。

### 5. 本地跑通流程

- 干什么：启动 3 机分布式 SFT。
- 做到什么程度：看到 loss 刷新；触发 eval；checkpoint 落盘；能找到日志/指标。
- 怎么验收：跑通，或失败但有完整命令、配置、日志、失败位置。

### 6. 跑后校对

- 干什么：和算法逐项对流程。
- 做到什么程度：把本地记录标成“一致 / 可接受差异 / 错误 / 未覆盖 / 待确认”。
- 怎么验收：错误项有改法；未覆盖项有后续安排。

### 7. 提炼切入点

- 干什么：从复刻过程找训练框架二开方向。
- 做到什么程度：至少写出 1 个有证据的切入点。
- 怎么验收：算法认可该切入点真实影响效率或稳定性。

## 向算法最少要什么

### 1. 环境与 `ms-swift`

- 源码仓库 / 分支 / commit / 安装命令。
- 相对官方 `ms-swift` 的 diff 或改动范围。
- patch 生效验证方式。
- Python / CUDA / PyTorch / NCCL / DeepSpeed 或 Megatron 版本。

### 2. 模型

- 生产训练模型名、模型族、Dense/MoE、多模态/文本。
- tokenizer、chat template、特殊 token、stop token。
- 是否需要手动注册模型。
- 本地建议用哪个 1B–7B 小基座，保证和数据/tokenizer/template 对齐。

### 3. 数据

- 处理好的小 train/eval 数据集，脱敏/抽样即可。
- 数据 schema 和 1–2 条样例。
- 自定义数据处理脚本入口、启动命令、关键参数。
- 原始输入到处理后输出的脱敏对照样例。

### 4. 训练流程

- 脱敏启动命令和主配置文件。
- 多机启动脚本或参数。
- eval 配置：频率、指标、是否自定义代码。
- checkpoint：保存频率、best/last、resume 规则。
- 监控：日志/面板入口，loss 之外有哪些指标，PPL 是否出现。

## 校对方式

逐项投屏本地记录，让算法只判断状态：

| 状态 | 含义 |
|------|------|
| 一致 | 与生产流程一致 |
| 可接受差异 | 因 3 台 5880、小模型、小数据导致不同，但不影响流程复刻 |
| 错误 | 本地理解或配置不符合生产流程 |
| 未覆盖 | 本次没跑到，如 resume、部署 |
| 待确认 | 算法需要后续补材料 |

固定问法：

```text
我本地记录是 X。
这个和你们生产流程是：一致 / 可接受差异 / 错误 / 未覆盖 / 待确认？
如果是差异或错误，应该改成什么？是否需要重跑？
```

校对顺序：

1. `ms-swift` 源码、commit、patch 是否对。
2. 模型、小基座、tokenizer、template 是否对。
3. 数据 schema、处理脚本、train/eval 是否对。
4. 3 机启动、rank、NCCL 是否对。
5. 训练配置、eval、checkpoint 是否对。
6. 监控指标、PPL 有无是否对。
7. 哪个问题最适合做成训练框架能力。

---

## 最终验收

满足这 4 条即可结束本阶段：

1. 本地 3 机小规模流程跑通；或失败但能定位失败环节并完成算法校对。
2. 训练流程关键记录齐全：安装、模型、数据、启动、eval、checkpoint、监控。
3. loss 与 PPL 有无有明确结论。
4. 至少 1 个训练框架二开切入点被算法认可。
