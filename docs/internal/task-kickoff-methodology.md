# 任务启动方法论

> 源自 2026-05 Kimi-K2.6 部署验证任务的复盘，适用于**技术可行性验证、环境部署测试**类工作。

---

## 根本原则

> **在目标环境上，用最少的步骤，验证最关键的那一个假设。其他一切都是噪声。**

动手之前，先用 30 分钟回答四个问题。没有答案，不开工。

---

## 四步框架

### 第一步：任务锁定（≤30 分钟，不动手）

把任务拆成下表，每行都要有明确答案：

| 问题 | 要求 |
|------|------|
| 要验证的技术组合是什么？ | 一句话，不允许任何变量模糊 |
| 验证"成功"的判断标准是什么？ | 具体的可观测结果（日志、输出、显存） |
| 验证"失败"的判断标准是什么？ | 具体的报错信息或超时条件 |
| 目标运行环境是哪台机器？ | 指定到具体机器，不允许"随便找一台" |
| 是否允许替换目标中的任意变量？ | 原则上：不允许。替换需要写明理由 |

**输出：一句不可改变的验收标准。** 把它写在文档顶部，任何时候偏离都要重新确认。

---

### 第二步：约束盘点（≤1 小时，收集信息，不动手）

针对目标环境和技术组合，逐项查清：

**机器约束清单：**
- [ ] 目标机器的驱动版本、CUDA 版本
- [ ] 是否有 root / Docker 操作权限
- [ ] 模型权重路径，目标机器是否可访问
- [ ] 磁盘空间是否充足

**框架/镜像约束清单：**
- [ ] 去官方 changelog / release notes 搜索目标功能的支持记录
- [ ] 去 GitHub issue tracker 搜索相关 bug 或已知限制
- [ ] 列出候选版本（≤3 个），每个旁边写明支持依据

**输出：一张候选版本表 + 每个版本的支持证据。** 把穷举试错压缩为只测 1-2 个最有依据的版本。

---

### 第三步：最短验证路径（动手前先写步骤）

在执行前把完整操作步骤写出来，格式如下：

```
步骤 N：[做什么]
  预期结果：[具体的成功表现]
  若偏离预期：[立刻停下，记录差异，再决定下一步]
```

**规则：**
- 每步都要有预期结果，执行时一旦偏离立刻感知
- 不允许在没有记录的情况下连续试错超过 2 次
- 每次试错前先问：这次改动的目的是什么？预期的变化是什么？

---

### 第四步：执行并记录

按步骤执行，每步完成后立刻记录：

| 记录项 | 内容 |
|--------|------|
| 实际结果 | 与预期是否一致 |
| 异常信息 | 完整报错（不截断） |
| 卡住点 | 卡在哪一步，具体现象 |
| 下一步判断 | 查文档 / 换方案 / 升级 |

---

## 补充原则：不抄不懂的参数

### 问题

从搜索结果或文档中照抄配置/命令，不知道参数的含义，出问题后无从定位，只能继续随机搜索。

### 区分两类参数

| 类型 | 定义 | 处理方式 |
|------|------|---------|
| **样板参数** | 行业通用、环境无关，错了也容易识别（端口、日志格式、超时默认值） | 可以先抄，出错后查标准文档即可 |
| **承重参数** | 和本次任务的核心假设强相关，错了会静默失败或让结论无效（量化格式 flag、LoRA dtype 兼容性、驱动相关 env var） | **必须理解后再用** |

### 快速判断方法

对照抄的每一个关键参数问自己：

> **如果这个参数设置错了，报错会是什么样子？**
> - 能回答 → 样板参数，可以先用
> - 不能回答 → 承重参数，先弄懂再用

### 理解的最低要求

对承重参数，能用一句话说清楚以下三点就够了：
1. **这个参数控制什么行为？**（不需要深入原理，知道它影响什么就行）
2. **为什么我的场景需要这个值而不是另一个值？**
3. **如果设错了，大概会出现什么现象？**

### 时间投入的判断

这不是要求每个参数都精通，而是对**承重参数做最低限度的理解**：

- 任务紧急：只看官方文档的参数说明（通常 2-5 分钟）
- 任务不紧急：看一篇讲这个参数设计背景的文章或 issue（10-20 分钟）
- 完全搞不懂：先记录"这个参数我不理解，风险标注"，再找人确认

## 反例：这次任务踩的坑

| 问题 | 根因 | 正确做法 |
|------|------|---------|
| 用 deepseek-v2-lite-chat 代替 Kimi-K2.6 | 没有锁定目标变量 | 第一步：写下不可改变的验收标准 |
| 在 L20 做实验，结论不能用到 H20 | 没有前置确认目标机器 | 第二步：机器约束盘点必须最先做 |
| 穷举镜像版本 | 没有查官方文档过滤候选版本 | 第二步：先收集支持证据再选版本 |
| 不知道卡在哪一步 | 没有预期结果，无法感知偏离 | 第三步：每步都写预期结果 |

---

## 快速自查问卡

开工前 5 分钟读一遍，全部打勾才能动手：

- [ ] 验收标准写在文档顶部了吗？（一句话，所有变量明确）
- [ ] 目标机器已确认，并且我会在那台机器上做实验？
- [ ] 候选镜像/版本有支持证据，不是靠猜？
- [ ] 操作步骤已写出，每步有预期结果？
- [ ] 步骤中每个承重参数，我能解释"设错了会出什么现象"吗？
