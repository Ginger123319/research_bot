### TP（Tensor Parallelism）

**是什么**（1-2 句）：把模型权重看作一个长方形，TP就是按照宽进行切分，每一份参数存放在不同的GPU上

**解决什么问题 / 没有它会怎样**（1-2 句）：单卡放不下一层参数，没有它，只能训练单卡可以训练的小模型；没法用有限的资源训练大模型

**图像/直觉**（可选——FFN 的 W1 / W2 怎么切、几张卡怎么协作）：W1按照输出维度切分，W2按照输入维度切分，计算出结果之后再累加


**关键工程事实**（2-4 条，**必须包含适用前提 / 边界**）：

- 一般来说，TP在机器内部使用，不期望跨机器通信，机器之间的通信带宽一般远小于机器内部的通信带宽，容易成为瓶颈

-TP时，输入需要复制到在各个卡上运算，运算结果都只是完整运算结果的一部分，最后通过all-reduce算法进行累加，再更新参数

### PP（Pipeline Parallelism）

**是什么**：把模型权重看作一个长方形，PP就是按照高进行切分，每一层参数存放在不同的GPU上

**解决什么问题**：单卡放不下所有层的训练场景

**图像/直觉**（可选——layer 怎么分到不同 GPU + micro-batch 流水线时序 + bubble 在哪）：均分到不同的GPU，流水线就是一个batch在各个GPU之间流转，遍历所有GPU才能得到一个前向结果，bubble就是当前只使用某个GPU上的某一层权重运算，那么其他GPU都是空闲的，就是bubble

```


```

**关键工程事实**（注意区分通信特征和 TP 的差异）：

- PP传递的是激活值和梯度，在模型层之间传递，相较于TP传输的中间结果，体积会小很多，机器间的通信带宽基本够用

---

### DP（Data Parallelism）+ 总卡数公式

**是什么**：将数据均分到每一个模型副本分片中进行计算，延续DDP中的思路

**解决什么问题**：训练速度慢

**图像/直觉**（可选——总卡数 = TP × PP × DP × CP；DP 是怎么"复制 N 份网格"的）：DP通过增加TPxPP这么多组机器来复制N份网格

```


```

**关键工程事实**：

- DP需要每一份数据都经过所有的模型参数计算，彼此独立，最终统一汇算

## 对照原文后的差异补充

> 第一次默写完之后填这一节。**不要重写全篇，只列"我漏了什么 / 写错了什么"**——漏的点和错的点就是你的真实学习成果，下次复习重点看这里。

### TP 的差异

- W1 列切 + W2 行切**正好接得上、不需要中间通信；而其他切法要么增加通信次数要么需要在激活函数之前做汇总，从而没法并行；**

**-** TP就是按照宽进行切分是最高维度的说法，具体到某个layer时，需要根据具体情况进行切分，比如线性层可以按照列切再行切，注意力计算中的QKV映射层，可以按照head进行切分，切分方法各不相同

### PP 的差异

- 为了环节PP切分工作时的bubble问题，常规的解决手段就是将一个大batch，拆分为N个micro-batch，按照时序依次出发进行前向计算
- 工程经验上micro-batch的数量设置为4倍的pp-size比较合适，可以将bubble率控制在10%以内

### DP / 总卡数公式的差异

- 总卡数=TP*PP*DP*CP
- DP需要完整副本，每个副本需要有完整的模型
- DP并不是让单步训练的速度变快，而是减少整体训练时间，通过数据并行训练，当然此时资源量是不用DP的时候的N倍

### 算账例子的差异

- 梯度的大小时BF16的，只有在要更新参数时，才会将梯度转换为FP32的精度
- 激活值的大小与batch_size,seq_len,embedding_size,hidden_size等几个变量直接正相关

-如果单卡在设置了各种并行策略之后还是放不下，能够采取的措施只有增加训练资源或者使用一些额外的降低显存占用的技术

- ZeRO-3：除了对模型参数的切分，还增加对优化器参数以及梯度的切分；梯度检查点（需要在计算梯度的时候重算一部分激活值）；CPU offload（兜底方案）

### 235B MoE 配方推导（2026-05-15 补，扩展到 EP 维度）

> 这一节是在原 mental model（只有 TP/PP/DP/CP）之上的**主动扩展**——补上 MoE 必需的 EP 维度。  
> 推导来源：读完 Switch Transformer 论文 + 自己用 64 卡 H200 / 235B MoE × 128 专家 的具体场景反推。

**目标**：64 卡 H200 上跑 235B MoE × 128 专家全参 SFT，反推合理的 (TP, PP, EP, DP) 组合

**约束**（5D 并行算式）：

- 总卡数 = TP × PP × EP × DP = 64
- MoE 的 **all-to-all 通信对带宽极敏感**（每个 token 都要跨 expert 路由）→ **EP 必须在同一台机器内**（用 NVLink，避免跨机 IB）
- 跨机器只走 PP（通信量最小，只传层间激活值/梯度）

**给定**：EP=2，DP=4（来自上层 trade-off——用 DP 副本数平滑 routing collapse 的概率；详见 `docs/scratch/2026-05-15-ai-output-3-moe-scenarios.md` 的「DP4EP2 是空间换稳定性」分析）

**推导**：

1. TP × PP = 64 / (EP × DP) = 64 / 8 = **8**
2. 候选 (TP, PP) ∈ {(8,1), (4,2), (2,4), (1,8)}
3. **关键判断**：如果选 (8,1)，PP=1 意味着一台机器装一个完整的 PP stage；但 DP=4 副本要 16 卡 = 2 台机器，EP=2 自然要跨这 2 台机器分布 → **EP all-to-all 必跨机** ❌
4. 解决：把跨机器的工作让给 PP，让 EP 留在机器内
5. 一台机器 8 卡 → 必须容纳"一个 PP stage 上的完整 EP"→ EP=2 × TP=4 = 8 卡刚好填满
6. 跨机器的工作让 PP 来做 → **PP=2**

**结论**：**TP=4, PP=2, EP=2, DP=4**（验证：4 × 2 × 2 × 4 = 64 ✓）

**专家分布**：

- 总专家数 = **128**（235B MoE 的固定值；注意不要和 122B MoE 的 256 专家混淆）
- 每个 EP rank 承担 128 / 2 = **64 个专家**
- 一台机器内（8 卡）放下完整的 128 个专家（两个 EP rank 各占 4 卡 TP，共同覆盖 128 专家）

**为什么这样排布是"用空间换稳定性"**（来自 5-15 推导）：

- 空间代价：DP=4 复制 4 份完整模型权重——空间增加
- 换来：
  1. EP=2 而非 EP=8 → 每个 EP shard 内专家数多（64 vs 16），天然负载方差小
  2. DP=4 拆 batch → 4 个 micro-batch 独立做路由，大数定律平滑 routing collapse 概率
  3. 极端情况"一轮训练所有 token 跑到一个专家"的概率从 EP=8 降到 EP=2 + 4 个 micro-batch 的乘积

**留待自己核实的细节**：

- 4 个 DP 副本之间的梯度同步路径是什么样的？（DP all-reduce 怎么跨机器走）每个副本之间将自己的梯度发送出去，接受其他剩余副本的梯度，拿到之后做个平均，然后用梯度去更新参数！
- **显存账没算**：235B 模型 BF16 总权重 ≈ 470GB；TP=4 + EP=2 切分后，每张 H200 上的参数量是多少？激活值 + 优化器状态加起来塞得进 80GB 显存吗？是否需要 ZeRO-1/2/3 + 梯度检查点？**这一条不算清楚，整个配方都是空中楼阁；TP4EP2，那么每张卡需要存放所有权重的1/8；激活值（得看batch-size，seq-len，out-dim）和优化器（得看是什么优化器，如果是Adam，并且是混合精度训练的话，就是存储一份fp32权重，权重大小的fp32动量以及方向参数，也就是6倍的bf16权重的大小）加起来再看！可能需要**ZeRO-1/2/3 + 梯度检查点，看起来显存不够用！
- capacity factor 取值？这会显著影响显存占用（容量越大每张卡上的 token 越多，激活值越大）这个值指的是expert的容量，容量越大能够支持参与计算的token的batch越大，那么batch越大，自然激活值就越大，一般都是取1！
