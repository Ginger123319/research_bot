### TP（Tensor Parallelism）

**是什么**（1-2 句）：把模型权重看作一个长方形，TP就是按照宽进行切分，每一份参数存放在不同的GPU上

**解决什么问题 / 没有它会怎样**（1-2 句）：单卡放不下一层参数，没有它，只能训练单卡可以训练的小模型；没法用有限的资源训练大模型

**简笔画 / 几何直觉**（FFN 的 W1 / W2 怎么切、几张卡怎么协作）：W1按照输出维度切分，W2按照输入维度切分，计算出结果之后再累加

```

**关键工程事实**（2-4 条，**必须包含适用前提 / 边界**）：

- 一般来说，TP在机器内部使用，不期望跨机器通信，机器之间的通信带宽一般远小于机器内部的通信带宽，容易成为瓶颈

-TP时，输入需要复制到在各个卡上运算，运算结果都只是完整运算结果的一部分，最后通过all-reduce算法进行累加，再更新参数

### PP（Pipeline Parallelism）

**是什么**：把模型权重看作一个长方形，PP就是按照高进行切分，每一层参数存放在不同的GPU上

**解决什么问题**：单卡放不下所有层的训练场景

**简笔画**（layer 怎么分到不同 GPU + micro-batch 流水线时序图 + bubble 在哪）：均分到不同的GPU，流水线就是一个batch在各个GPU之间流转，遍历所有GPU才能得到一个前向结果，bubble就是当前只使用某个GPU上的某一层权重运算，那么其他GPU都是空闲的，就是bubble

```


```

**关键工程事实**（注意区分通信特征和 TP 的差异）：

- PP传递的是激活值和梯度，在模型层之间传递，相较于TP传输的中间结果，体积会小很多，机器间的通信带宽基本够用

---

### DP（Data Parallelism）+ 总卡数公式

**是什么**：将数据均分到每一个模型副本分片中进行计算，延续DDP中的思路

**解决什么问题**：训练速度慢

**简笔画 / 算式**（总卡数 = TP × PP × DP × CP；DP 是怎么"复制 N 份网格"的）：DP通过增加TPxPP这么多组机器来复制N份网格

```


```

**关键工程事实**：

- DP需要每一份数据都经过所有的模型参数计算，彼此独立，最终统一汇算

### 算账例子：72B 全参 SFT × 16 张 L20 能不能跑

```

在72B参数的模型采用混合精度训练时，模型参数为BF16，那么模型权重（144GB）+优化器参数（2份FP32模型权重大小存放M和V+1份FP32的模型权重大小）+梯度一份模型权重大小+激活值等，大越就是8份完整的BF16权重大小即1152GB；当TP=2，PP=8，DP=1时，每张卡需要承载的运行态显存占用为1152/16=72GB，单卡48GB显存，放不下，因此无法跑起来

## 对照原文后的差异补充

> 第一次默写完之后填这一节。**不要重写全篇，只列"我漏了什么 / 写错了什么"**——漏的点和错的点就是你的真实学习成果，下次复习重点看这里。

### TP 的差异

- W1 列切 + W2 行切**正好接得上、不需要中间通信；而其他切法要么增加通信次数要么需要在激活函数之前做汇总，从而没法并行；**

**-** TP就是按照宽进行切分是最高维度的说法，具体到某个layer时，需要根据具体情况进行切分，比如线性层可以按照列切再行切，注意力计算中的QKV映射层，可以按照head进行切分，切分方法各不相同

### PP 的差异

- 为了环节PP切分工作时的bubble问题，常规的解决手段就是将一个大batch，拆分为N个micro-batch，按照时序依次出发进行前向计算
- 工程经验上micro-batch的数量设置为4倍的pp-size比较合适，可以将bubble率控制在10%以内

### DP / 总卡数公式的差异

- 总卡数=TP*PP*DP*CP
- DP需要完整副本，每个副本需要有完整的模型
- DP并不是让单步训练的速度变快，而是减少整体训练时间，通过数据并行训练，当然此时资源量是不用DP的时候的N倍

### 算账例子的差异

- 梯度的大小时BF16的，只有在要更新参数时，才会将梯度转换为FP32的精度
- 激活值的大小与batch_size,seq_len,embedding_size,hidden_size等几个变量直接正相关

-如果单卡在设置了各种并行策略之后还是放不下，能够采取的措施只有增加训练资源或者使用一些额外的降低显存占用的技术

- ZeRO-3：除了对模型参数的切分，还增加对优化器参数以及梯度的切分；梯度检查点（需要在计算梯度的时候重算一部分激活值）；CPU offload（兜底方案）
