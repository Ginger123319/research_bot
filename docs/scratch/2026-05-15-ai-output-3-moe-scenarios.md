## 5-15 验收过程产出（值得记的部分）

5-15 用户完成了对 Q3/Q4 的回答（路由机制 + 空间换稳定性），其中**值得作为未来消化锚点**的几条：

1. **routing collapse 的极端描述**："纯 EP=8 时，最极端情况：一轮训练所有 token 都去到某个 GPU 对应的专家"——这是 MoE 训练失败的具体边界
2. **大数定律平滑**："DP=4 拆 batch → 4 个 micro-batch 路由差异相互抵消"——为什么 DP 副本数能减少 routing 方差
3. **路由全流程**：`router logits → softmax → argmax → capacity 矩阵 → gather → all-to-all → expert layer → all-to-all 回传`

这三条已通过验收，不在"已知问题"里。

## 原文（不要修改本节，留作未来对照样本）

> 下面这段是 AI 直接输出的原文，**保留不动**——未来你自己写完一版之后，要拿这个原文做对照。

```
场景1：内存充足，数据充足

选择：DP=4, EP=2
理由：吞吐量和稳定性更重要

场景2：内存紧张

选择：EP=8（或更大）
理由：必须减少每GPU的专家数
即使负载不均，也没办法

场景3：模型巨大（如DeepSeek-V3）

选择：多维并行 DP × EP × TP × PP
理由：需要综合权衡所有因素


混合并行 DP=4, EP=2 的好处：

吞吐量提升：4个batch并行，4倍吞吐
负载平滑：多batch的路由差异相互抵消，GPU利用率更均衡
容错性：单个batch的极端路由不会毁掉整体性能
但不是减少每GPU的专家数（实际上增加了）。

这是一个用空间换稳定性的策略。
```
