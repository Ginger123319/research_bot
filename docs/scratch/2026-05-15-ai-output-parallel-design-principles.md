## 原文（不要修改本节，留作未来对照样本）

> 下面这段是 AI 直接输出的原文，**保留不动**——未来你自己写完一版之后，要拿这个原文做对照。

```
四、参数设计原则

原则1: 根据硬件拓扑设计

黄金法则：
  TP在机器内（利用NVLink）
  PP跨机器（减少跨机通信）
  DP最外层（梯度同步不频繁）

示例拓扑（64 GPU = 8机器 × 8卡）:
配置: DP=4, TP=8, PP=2

机器0-1: DP组0
  机器0: [TP=8, PP=0] ← 8卡通过NVLink切分宽度
  机器1: [TP=8, PP=1] ← 8卡通过NVLink切分宽度
         ↑
      跨机器用PP（通信量小）

机器2-3: DP组1（参数副本）
机器4-5: DP组2（参数副本）
机器6-7: DP组3（参数副本）
         ↑
      跨DP组同步梯度（每step一次）

原则2: 优先满足内存约束

决策树:
1. 单GPU能装下模型？
   YES → 仅用DP
   NO  → 继续
2. 机器内8卡能装下（TP=8）？
   YES → TP=8 + (可选DP)
   NO  → 继续
3. 需要多台机器才能装下？
   → 使用 PP（跨机器）+ TP（机器内）

4. 还有剩余GPU？
   → 加入DP提升吞吐量
   → 但确保TP=8已填满单机

原则3: 平衡三种并行

经验公式:
总GPU数 = DP × TP × PP

约束:
  TP ≤ 单机GPU数（通常≤8）
  PP = 需要的stage数（通常2-16）
  DP = 剩余GPU数 / (TP × PP)

目标:
  最小化跨机器通信
  最大化GPU利用率
  满足内存约束

原则4: 避免反模式

❌ 反模式1: 跨机器TP
   TP=4, 分布在2台机器
   → 延迟高，带宽不够

❌ 反模式2: 单机内过度PP
   单机8卡，PP=8, TP=1
   → 浪费NVLink，bubble大

❌ 反模式3: DP>1但内存紧张
   模型刚好装下，还用DP=2
   → 内存溢出风险

❌ 反模式4: TP过大
   TP=32
   → 通信开销超过计算收益

✓ 正确模式:
   机器内: TP=8（打满NVLink）
   跨机器: PP=N（分层）
   外层: DP=M（数据并行）
```
