```
二、指标间的关系

层次结构

              MFU (顶层综合指标)
               ↑
               |
    ┌──────────┼──────────┐
    |          |          |
 计算效率   通信效率    内存效率
    |          |          |
    |          |          |
GPU利用率  Comm/Comp   内存利用率
Throughput   带宽利用   激活值管理
           Scaling Eff  优化器选择
           Pipeline Eff

相互影响

提高Throughput的方法：
  ↓ 增大batch size
  → 需要更多内存 (内存效率↓)
  → 减少通信频率 (通信效率↑)
  → GPU计算增加 (GPU利用率↑)
  → 最终 MFU↑

提高Scaling Efficiency：
  ↓ 优化通信策略
  → 通信时间减少 (通信效率↑)
  → GPU等待减少 (GPU利用率↑)
  → 最终 Throughput↑, MFU↑

激活重计算：
  ↓ 节省内存
  → 可增大batch (Throughput↑)
  → 但增加计算 (GPU利用率↑，但重复计算)
  → 权衡：内存↑ vs 计算时间↓

三、不同并行策略的指标特点

Data Parallelism (DP)

优势指标：
  ✓ Scaling Efficiency：最好（理论线性）
  ✓ GPU Utilization：高（无需等待）
  ✓ Pipeline Efficiency：N/A（无pipeline）
劣势指标：
  ✗ Memory Efficiency：差（参数冗余）
  ✗ Communication Efficiency：跨机器时差
适用场景：
  - 单GPU能装下模型
  - 追求最大吞吐量
  - 机器内使用

Tensor Parallelism (TP)

优势指标：
  ✓ Memory Efficiency：优秀（均匀分片）
  ✓ GPU Utilization：高（计算密集）
劣势指标：
  ✗ Communication Efficiency：通信频繁
  ✗ Scaling Efficiency：差（TP>8后下降明显）
适用场景：
  - 模型太大单GPU装不下
  - 必须在机器内使用（NVLink）
  - 通常TP≤8

Pipeline Parallelism (PP)

优势指标：
  ✓ Communication Efficiency：优秀（通信少）
  ✓ Memory Efficiency：好（按层分片）
  ✓ Scaling Efficiency：好（可跨机器）
劣势指标：
  ✗ Pipeline Efficiency：有bubble
  ✗ GPU Utilization：低于其他方法
适用场景：
  - 需要跨机器训练
  - 模型层数足够多
  - 可容忍bubble开销


总结：评估三原则

1. 先看MFU（整体效率）

MFU是最重要的综合指标
  > 50% → 系统已高度优化
  40-50% → 正常生产水平
  30-40% → 有明显优化空间
  < 30% → 存在严重问题

2. 再看瓶颈（定位问题）

GPU利用率 → 计算是否饱和
通信/计算比 → 通信是否瓶颈
内存利用率 → 资源是否充分
扩展效率 → 多卡协作是否高效

3. 最后优化（针对性改进）

优化优先级：
  配置问题 > 算法问题 > 工程问题

  先确保：
    - 并行策略正确（TP机器内，PP跨机器）
    - Batch size合理（显存85-95%）
    - 混合精度开启

  再追求：
    - 高级算子优化
    - 通信细节优化
    - 极致内存优化

最终目标：用最短时间、最少资源，训练出最好的模型！
```
