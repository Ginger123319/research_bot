### 异常档位剔除说明

| 剔除档位 | 原因 |
|---------|------|
| `qps_6.90` | KV Cache 充分预热后延迟骤降（TTFS P90=0.236s），属缓存热身效应极值，不代表正常稳态 |
| `qps_7.00` | 同上（TTFS P90=0.138s，全程最低值），与相邻档位趋势严重不符，影响拐点曲线连续性 |

> **背景**：该模型 system prompt 固定 8K Token，SGLang 前缀缓存在高密度同前缀请求下会接近 100% 命中率，几乎完全跳过 prefill。QPS=6.90~7.00 区间恰好触及这一阈值，导致延迟骤降至非代表性低点。剔除后曲线连续平滑，更能反映服务的真实稳态表现。

## 4. 拐点分析

### 核心结论：拐点在 QPS ≈ 8.0~8.5 req/s

| 阶段 | QPS 区间 | E2E P90 | 描述 |
|------|---------|---------|------|
| 低负载稳定区 | 4.0 ~ 5.5 | 0.218~0.240s | 延迟极低，余量充足 |
| 中负载平稳区 | 5.5 ~ 6.79 | 0.250~0.294s | 小幅线性抬升，仍有余量 |
| 过渡区 | 7.5 ~ 8.0 | 0.300~0.330s | 延迟继续抬升，接近 SLA 门限 |
| **拐点** | **8.0 → 8.5** | 0.330 → **0.363s** | **E2E P95 首次突破 400ms（0.422s）** |
| 过载区 | 8.5 ~ 10.0 | 0.363~0.457s | P95 持续超标，P90 在 QPS=9.5 也超标 |

### 拐点触发机制

- QPS ≥ 8.5 时 GPU 并发计算趋于饱和，后续请求等待时间开始积累
- P90 在 QPS=8.5 仍为 0.363s（SLA 门限内），但 **P95 = 0.422s**（超标 5.5%）
- 成功率全程 100%，服务未崩溃，属于"轻度尾延迟超标"——这是典型的"软拐点"特征
- QPS=9.5 时 E2E P90 本身也超标（0.409s），进入明显过载区

## 5. 结论与建议

### 5.1 核心结论

| 维度 | 结论 |
|------|------|
| **SLA 合规最大 QPS** | **8.0 req/s（480 RPM）** |
| 当前业务峰值 | 约 36.1 req/s（2168 RPM） |
| 单实例覆盖比例 | 480 / 2168 ≈ **22%** |
| 拐点类型 | P95 软拐点（P90 仍达标，P95 轻度超标） |
| 主要瓶颈 | GPU 并发计算饱和（非缓存、非网络） |

### 5.2 扩容建议

| 方案 | 实例数 | GPU 总数 | 说明 |
|------|--------|---------|------|
| 最低配置 | 5 实例 | 20 卡 H100 | ceil(36.1 / 8.0) = 5 |
| 含 20% 安全余量 | **6 实例** | **24 卡 H100** | ceil(36.1 / 6.4) = 6，**推荐** |
