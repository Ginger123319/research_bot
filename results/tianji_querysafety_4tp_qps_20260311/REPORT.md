## 4. 拐点分析

### 结论：**本次测试范围内未发现服务拐点**

全部 30 档位在 E2E P90、TTFS P90、成功率三项指标上均大幅优于 SLA 门限，延迟绝对值极低：

- **E2E P90 全程 ≤ 294ms**（门限 400ms），余量 26%+
- **E2E P95 全程 ≤ 329ms**，全程满足 400ms 门限，余量 18%+
- **TTFS P90 全程 ≤ 120ms**（门限 1,500ms），余量超过 90%
- **成功率全程 100%**，无任何超时或失败

### 关键异常：QPS=6.9 和 7.0 时延迟反而骤降

P90、P95、P99 在 QPS=6.90~7.00 出现跨百分位的一致性骤降：

| QPS 档位 | TTFS P90 | E2E P90 | E2E P95 | E2E P99 | 现象 |
|---------|----------|---------|---------|---------|------|
| 6.48 | 120ms | 285ms | 314ms | 734ms | 平稳段 |
| 6.59 | 120ms | 294ms | 329ms | **807ms** | 阶段高点（P99 峰值） |
| 6.69 | 118ms | 288ms | 324ms | 747ms | 略降 |
| 6.79 | 116ms | 284ms | 318ms | 755ms | 略降 |
| **6.90** | **107ms** | **245ms** | **270ms** | **554ms** | **明显下降（转折点）** |
| **7.00** | **60ms** | **138ms** | **146ms** | **457ms** | **全程最低值** |

**解释**：这是 SGLang KV Cache **缓存命中率阶跃式锁定**现象——

- **QPS 4.0~6.59 阶段**：缓存命中率高但不稳定，偶发的 cache miss 导致尾延迟（P95/P99）周期性波动，P99 在 6.59 时达到峰值 807ms
- **QPS=6.90 出现转折**：请求密度达到阈值，8K Token prefix 被系统保持在显存热区，cache miss 概率骤降，P99 从 807ms 降至 554ms
- **QPS=7.00 发生质变**：TTFT P90 从 120ms 骤降至 60ms（减半），说明 8K Token 前缀 prefill 几乎被 100% 跳过，请求到达后仅需计算几十个 user token，E2E P95 从 329ms 降至 146ms（降幅 56%）

### 轻微阶跃（非拐点，属正常波动）

在 QPS ≈ 5.03 处，E2E P95 从 ~249ms 跳至 ~302ms（+21%），并在 5.14~6.59 之间稳定维持在 306~329ms 区间。
这是随 QPS 升高批量处理中偶发排队时延增加的表现，**并非服务能力拐点**，E2E P90 同期仅从 224ms 升至 294ms，完全在 SLA 余量范围内。

## 5. 对照实验建议

### 当前测试局限

当前 4TP 单实例在 QPS=7.0 时**仍未到达服务极限**，测试设计基于业务峰值 2168 RPM（≈36.1 req/s）的保守估计，但实际真正峰值可能更高。

### 后续建议

#### 建议 A：扩大 QPS 范围重跑 4TP 单组
- 将 QPS 范围从当前 `4.0~7.0` 扩展至 `7.0~20.0`（或更高）
- 找到 4TP 实例的真正拐点（成功率 <99% 或 TTFS P90 非线性抬升）

#### 建议 B：等待 4DP 实验完成后做横向对比
- `tianji_opti_qps_20260312_111300`（1TP×4DP）实验完成后，使用 `multi_exp_compare.py` 进行 4TP vs 4DP 对比
- 核心问题：**4TP 单实例 vs 4DP 多副本，哪种配置在单位 GPU 资源下承载能力更高？**
- 重点对比：相同 GPU 总数（4卡）下，各自 SLA 最大 QPS
